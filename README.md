# 共享空间日历 v2.0

一个共享日历。

- 多用户账号
- 多个共享空间
- 空间邀请与加入申请
- 所有者、管理员、普通成员权限
- 每个空间独立的成员颜色、日程和 AI 配置
- 月视图、日期详情和简化时间轴
- 规则语义录入，可选 AI 增强
- Cloudflare KV 中一份完整 JSON，不使用 R2、D1、SQL 或迁移文件

## 一、主要功能

### 账号与空间

- 首次打开时创建平台管理员账号和第一个空间。
- 其他用户可以注册自己的账号。
- 用户可以创建多个空间并随时切换。
- 空间管理员可以搜索已有用户名并发送邀请。
- 用户也可以输入空间邀请码申请加入，由管理员审批。
- 旧版“三个固定账号”数据会自动迁移到一个“原三人共享空间”。

### 权限

- 空间所有者：管理空间、成员、角色、AI，并可为多人安排日程。
- 空间管理员：管理成员和 AI，并可为多人安排日程。
- 普通成员：只能直接创建、修改和删除自己的日程；邀请别人参加时，需要走邀请逻辑。
- 平台管理员：管理平台账号状态和密码重置。

### 日历界面

- 月历采用中性浅灰透明底色，不与成员颜色混淆。
- 日期固定在格子左上角。
- 每位成员可使用调色盘选择自己的颜色。
- 颜色与现有成员过于接近时会提示更换。
- 每天最多展示三行摘要；成员较多时折叠为“还有 N 人有安排”。
- 点击日期可以查看当天完整详情。
- 日视图按成员分行，展示 06:00—24:00 的简化时间轴。

### 规则语义录入

不配置 AI 也能使用。日期是支持任意有效日期：

- `3号去体检`
- `18号下午2点到4点开会`
- `31号晚上7点看电影`
- `8月6号下午3点半健身`
- `2027年3月8号出差`
- `周日吃饭`
- `下周三晚上7点打球`
- `下下周五聚餐`
- `今天、明天、后天`

规则：

- 只说“几号”时，使用当前正在查看的月份和年份。
- 说“几月几号”但没说年份时，使用当前正在查看的年份。
- “周几”定位到本周对应日期。
- “下周几”“下下周几”分别顺延一周、两周。
- 无效日期会拒绝创建，例如 `2月30号`。
- 未说明时间时默认全天。
- 普通成员即使在文字中写了其他空间成员，后端也只允许给本人直接创建。

### 可选 AI

AI 不是必需项。空间所有者或管理员可以为当前空间配置：

- API URL
- Model Name
- API Key

系统优先使用本地规则；规则无法可靠判断时，再调用兼容 OpenAI 格式的接口。普通成员不能通过 AI 绕过权限给别人强制安排日程。

## 二、数据保存

所有运行数据序列化为一份 JSON，保存在 Cloudflare Workers KV 的键：

```text
calendar-data.json
```

其中包括：

- 用户和密码哈希
- 登录会话
- 空间及成员关系
- 空间邀请和加入申请
- 日程及参与成员
- 成员颜色
- 空间 AI 配置

代码升级和重新部署不会主动清空 KV 数据。

## 三、上传到 GitHub

1. 解压项目。
2. 在 GitHub 新建空仓库。
3. 将本目录里的全部文件上传到仓库根目录。
4. 提交到 `main` 分支。

仓库首页应直接看到：

```text
src/
public/
package.json
wrangler.jsonc
README.md
```

不要在仓库外面再套一层项目文件夹。

## 四、连接 Cloudflare 部署

在 Cloudflare 的 **Workers & Pages** 中导入 GitHub 仓库，填写：

```text
Build command: npm run build
Deploy command: npx wrangler deploy
Root directory: 留空
Build output directory: 不填写
```

`wrangler.jsonc` 已声明 `CALENDAR_KV`。部署时由 Wrangler 自动配置 KV 资源，无需创建 R2、D1、SQL 表或执行迁移。

部署完成后打开 Worker 地址：

1. 创建平台管理员账号。
2. 创建第一个空间。
3. 让其他用户注册账号。
4. 通过用户名邀请，或将空间邀请码发给对方。

## 五、本地检查

```bash
npm install
npm run build
npm run dev
```

`npm run build` 会同时编译前端并检查 Worker TypeScript 类型。
